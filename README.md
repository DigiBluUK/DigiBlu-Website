# DigiBlu Website

Marketing site for **DigiBlu**, a UK AI/digital transformation consultancy. Single-file HTML/CSS/JS, no build tooling, no framework — the whole site is `index.html` plus a handful of hand-authored generated pages.

## Structure

```
index.html          The site (source of truth — edit this)
assets/              Fonts, images, and the shared stylesheet (site.css)
case-studies/        8 generated, standalone case study pages
blog/                 7 generated, standalone blog post pages
legal/                5 generated, standalone legal policy pages
generate-static-pages.js   Regenerates the three folders above from index.html
sitemap.xml, robots.txt    Also generated by the script above
digiblu-site.html    A separate, self-contained build for claude.ai Artifacts only — not part of the deployed site (see below)
```

## Local development

```bash
npx http-server -p 4173
```

Then open `http://localhost:4173`. Opening `index.html` directly via `file://` will not render correctly — the page relies on relative fetches that need a real HTTP server.

If you edit content that lives in `index.html`'s `CASE_STUDIES`, `BLOG_POSTS`, or `LEGAL_DETAILS` objects, re-run the generator afterward so the standalone pages stay in sync:

```bash
node generate-static-pages.js
```

## Deploying

**Deploy `index.html` and the folders next to it — never `digiblu-site.html`.**

| File | Purpose | Deploy? |
|---|---|---|
| `index.html` | The real website: full `<head>` (title, meta, OG tags, favicon, structured data), links `assets/site.css`. | **Yes.** |
| `digiblu-site.html` | A separate build for previewing this project as a claude.ai Artifact. Every asset is base64-inlined into one file and the `<head>` is stripped entirely (no title, no favicon, no SEO tags). | **No.** |

Upload the whole project folder — a host like Netlify or GitHub Pages needs `index.html`, `assets/`, `case-studies/`, `blog/`, `legal/`, `sitemap.xml`, and `robots.txt` all present, since the generated pages reference `assets/site.css` via a relative path.

`sitemap.xml` and `robots.txt` currently hardcode `https://digiblu.com/`. If you deploy to a different domain (a Netlify preview URL, a staging subdomain, etc.), update `SITE_ORIGIN` at the top of `generate-static-pages.js` and re-run it so those files point at the right place.

## Status

This is a working prototype, not yet wired to a backend. In particular, **the contact form does not send anywhere** — submitting it shows a success message but nothing is transmitted, stored, or emailed. Wire that up before sharing this outside the team.
